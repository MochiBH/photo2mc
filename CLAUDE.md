# Jungle coach

Single script, `riot_jungle_report.py` (Python 3, standard library only). See README.md.

- Run: `python riot_jungle_report.py "Name#TAG"`; add `--offline` to reuse `data/`.
- Never put a Riot key in code or commits. The script sends `RIOT_API_KEY` if set, otherwise relies on the environment's network secret for `X-Riot-Token`.
- Riot rejects the default Python User-Agent with 403; keep the custom one in `api_get`.
- Zones live in `raw_zone` (blue base bottom-left, river x + y = 14800, top side y > x). The report prints a zone check against real turret and epic-monster positions; keep it at 100% when changing thresholds.
- Timeline frames are one per minute, so "near me" counts are approximate (radius `NEAR`). Voidgrub kills are one event per grub.
- `data/` and `out/` are git-ignored (raw match data includes other players).

## Website (`app/`)

- React 19 + Tailwind 4 + Motion on Vite, deployed on Vercel with Root Directory `app`. Supabase for logins and data. See README "The website".
- `app/src/wm/` holds the Watermelon UI components (adapted, MIT). New UI should reuse them and their motion style (spring pills, blur-in).
- `app/src/fx/` holds the anime.js effects: `backdrop.jsx` (aurora + canvas dot grid; `ripple()` sends a wave through it), `fx.js` (`burst`, `shake`, `rippleFrom`, `startSheen`), `text.jsx` (`SplitTitle`, `Scramble`), `ring.jsx` (self-drawing gauge), `draw.js` (`useDrawIn` for `data-draw` strokes and `data-pop` marks). Use these for new showpiece motion; keep Motion for layout and presence. Everything in `fx/` must stay still under `prefers-reduced-motion` (the `calm` flag).
- Phone performance rules (the site was slow on an iPhone 14 until these were followed; `node scripts/perf.mjs` on a demo build measures it, compare before and after a change):
  - Anything that runs forever moves by `transform` or `opacity` in a CSS animation, never by a property that repaints (`background-position`, a custom property, `width`) and never by a script setting styles every frame. The aurora lights, `.glow-ring`, `.bar-sheen` are the patterns to copy.
  - No `filter: blur()` on anything large or long-lived. The aurora lights and `.glow-halo` are pre-blurred gradients drawn small and scaled up; `blurred()` in `backdrop.jsx` works out the falloff.
  - A Motion blur-in must end with the filter removed: spread `SHARP` from `src/ui.jsx` into the `animate` target. A leftover `blur(0px)` on a page-sized element makes Safari draw the whole page through a filter.
  - Card entrances are the CSS animation `rise-in` (`Screen` and `Rise` in `src/ui.jsx`), not Motion variants; `Screen` marks cards that start below the screen `data-still` so they do not animate.
  - The map (`views/Rift.jsx`) is stacked layers: the Rift, an optional `under` layer, and the marks. Put anything that animates in the upper layers, not in the base drawing.
- Fonts are bundled from `@fontsource-variable/*` (`src/fonts.css`, preloaded in `index.html`); do not add Google Fonts links. `vercel.json` caches `/assets` for a year and `/data` for an hour.
- `session.jsx` keeps the signed-in player's profile and stats in `localStorage` (`jc.me`) so a return visit renders at once and refreshes in the background; it is removed on sign-out. Saved state is not written to the account until the account's copy has been read.
- The design is dark only: tokens in `src/index.css`, lime for actions and wins, melon pink only for deaths, losses and the enemy, cyan and violet as atmosphere. Display type is Unbounded (`font-display`), used for the title, hero numbers and timers only.
- `app/src/session.jsx` owns sign-in, the profile, stats, the sync loop and per-player saved state (`useSynced`). Nothing personal is hard-coded in views; everything comes from `useSession().stats` for the active role.
- Server: `app/api/sync.js` (Vercel function) calls `app/server/sync.mjs`, `riot.mjs` and `analysis.mjs`. `analysis.mjs` is a port of `riot_jungle_report.py`; `scripts/check-analysis.mjs` must keep reporting that it matches. Schema and row-level security are in `app/supabase/schema.sql`.
- Sign-in is by username and password. `app/server/players.mjs` (shared by browser and server) holds the allowed usernames and maps each to a made-up address on a reserved domain; accounts are created by hand in SQL (`app/supabase/add-player.sql`). Never write a player's password into code, tests, docs or commits.
- The server holds no database secret. `api/sync.js` creates a Supabase client with the public key plus the caller's token and does everything as that player under row-level security; it refuses accounts that are not on the player list. The only server secret is `RIOT_API_KEY`. Only `VITE_*` values reach the browser.
- Live: https://jungle-coach-forge-quant.vercel.app (Vercel project `jungle-coach`, team Forge Quant, deploys from `main` on every push; standard deployment protection, so the production address is public and previews are not). Supabase project `jungle-coach` (ref `xaqqahmfcqfupycwlsxy`, org Forge Quant, free plan). Checks: `scripts/check-live.mjs <username>` (sign in + real sync, no Vercel), `scripts/check-site.mjs <username>` (the deployed `/api/sync`), `scripts/check-teams.mjs <username> <picture>` (the deployed `/api/teams`), `scripts/shot-live-site.mjs <username> [tab]` (sign in through the live site in a browser). They take the password from `PLAYER_PASSWORD`; never hard-code it.
- Roles: the coached roles are `ROLES` in `server/roles.mjs` (jungle, support, top), shared by server and browser; `ROLE` in `src/lib/roles.js` holds each one's names. `src/lib/roles.js` (rules, checkpoints), `src/lib/insights.js` (leaks generated from stats), `src/lib/content.js` (course per role), `src/lib/live.js` (build and plan engine for any champion). The header switch shows `session.roles`: the profile's main role, any other coached role with games, and the one on screen. `profiles.role` is the main role (a check constraint lists the allowed values); `mains` is one list across roles, and each screen filters it by the role's champion pool. Nunu and Kha'Zix jungle use the hand-tuned rules in `src/lib/legacy.js`, which is generated by `scripts/extract-legacy.mjs` from `scripts/legacy-page.html`.
- Games: ranked solo (queue 420) and normal draft (queue 400), `QUEUES` in `server/analysis.mjs`; Swiftplay is left out because its timers differ. Each analysed game carries `queue`. Saved stats are `{ jungle, support, top, normal: { ... }, both: { ... } }`, one entry per role in `ROLES` in each set: ranked at the top level (older clients and older saved rows have only that), built by `allStats` in `server/sync.mjs`. The browser picks a set with `statsFor` in `src/lib/queues.js`; the choice is the `viewQueue` saved state, default `both`, and the switch sits above Home and Map (`App.jsx`). Labels come from `queueWords(stats)`, never from a hard-coded "ranked".
- Top lane: everything a laner is judged on comes from version 3 of the analysis (`ANALYSIS_VERSION`): `cs_diff` and `farm[m].cs` (all CS against the lane opponent), `lane` (`plates` taken and lost on the outer towers only, `tower` minutes for each outer tower, `solo_kills` before 15:00), and on each death `n` (enemies with kill credit) and `jg` (their jungler was one of them). A "ganked" death is `jg`; a "lost 1v1" is `n === 1` without `jg`. Every lane tower has plates this season, so the outer one is picked by distance from its own base (`OUTER_FROM_BASE`). `row.mjs` carries these to the rules as `cs`, `csd10`, `gd15`, `gk`, `sd`, `sk`, `pl`, `tw`; rows saved before version 3 lack them, so code reading them must cope with `undefined`. In `live.js` a top-lane AD fighter is style `bruiser` with its own counter items; `laneRead` and `jungleRead` write the matchup from the champion tags, and `tunedTop` adds the Kled and Renekton notes. Top builds are `roles.top` in `champ-builds.json` (`pulled_top` is their date).
- Review (`views/Review.jsx`, data in `src/games.jsx`): the record of every game. It reads the player's own `player_games` rows straight from Supabase under row-level security (a few fields for the list, the full `analysis` when a game is opened) and writes `note` and `reviewed_at` back to the same row. `lib/review.js` turns one game's analysis into takeaways and plain sentences. `server/row.mjs` (shared with the browser) is the compact row the rules in `lib/roles.js` test, so one game is judged exactly as the lists are.
- Every position is analysed and saved (`ROLE_POSITION`, `roleIn` in `server/analysis.mjs`); only the coached roles feed the stats (`listGames` in `api/sync.js`). The browser asks for a fresh sync when its saved stats lack a role in `ROLES`. `role` is `skip` for a game with nothing to review. Bump `ANALYSIS_VERSION` when the saved analysis gains a field: the sync redoes older rows (`player_games.v`) a few per call. `/api/sync?depth=N` looks at the latest N (20 to 100) games of each kind; the Review tab raises it and the choice is saved as `reviewDepth`.
- The live tracker (`views/Track.jsx`) takes no objective taps: `objectives(t)` is the first spawn of each objective on the game clock. Taps were removed because nothing in `lib/live.js` read them. Deaths and behind/even/ahead are still entered by hand; only behind/even/ahead changes the build and plan.
- Teams from a picture (Live > Teams, the `Snap` card in `views/Live.jsx`): `lib/snap.js` shrinks the picture in the browser (`shrink`) and places what comes back into the lane rows (`placeTeams`); `session.api('/api/teams', ...)` posts it with the player's token. `api/teams.js` checks the player exactly as `api/sync.js` does, then `server/teams.mjs` asks a vision model for the champions as JSON (`SCHEMA`) through Vercel AI Gateway, using the official `@anthropic-ai/sdk` pointed at the gateway and authenticated with the request's `x-vercel-oidc-token` (or `AI_GATEWAY_API_KEY` if set), so there is no model key anywhere. The picture is never stored.
  - Models are tried in the order of `MODELS`: Claude (`CLAUDE`) first, then `FREE`. The gateway's free tier refuses every Claude model with a 403, so until the Vercel team buys AI Gateway credit the picture is read by the first `FREE` model; with credit, Claude answers and no code changes. Each model is asked in several forms (`forms`), because the gateway does not take every option for every model. The answer carries `model` and `reader`, and the card shows the reader.
  - The gateway host is not reachable from this sandbox. Test the real call through the deployed site with `scripts/check-teams.mjs <username> <picture> [role]`; the function's runtime log says which models and forms were passed over. In a demo build `session.api` returns a stand-in answer. Real champion art cannot be fetched here either, so pictures made in the sandbox only have champion names as text.
- Course files in `app/public/data/` are plain scripts loaded by `index.html`: `lessons.js`/`bank.js`/`leaks.js` (jungle), `support-lessons.js`/`support-bank.js`/`rell-bank.js`, `top-lessons.js`/`top-bank.js`/`kled-bank.js`/`renekton-bank.js`, and `player-leaks.js` (questions written from one player's games, keyed by Riot ID and then by role). A lesson's `quiz` ids must exist in that role's bank, and ids are unique across every bank.
- Drill questions: `opts[0]` is correct, `why` explains the right answer, and `no` has one line per wrong option in order (`no[0]` is for `opts[1]`). Every question in every bank must have `no`; `Drills.jsx` shows them all after an answer.
- Data in `app/public/data/`: `champ-builds.json` (OP.GG builds per champion and role, item prices), `builds.js` (hand-written champion tags), course files per role.
- Check with a demo build: `node scripts/make-demo.mjs`, `VITE_DEMO=1 npx vite build`, then `node scripts/shot.mjs <tab> [light|dark] [steps file] [jungle|support|top]`: it must report scrollWidth 400 and no errors. `make-demo.mjs` takes a jungler, a support, a region and a top laner (Riot IDs); the demo build shows all three roles. `node scripts/perf.mjs` on the same build reports frames and drawing work per scenario. Outside this sandbox Node needs no proxy flags; here use `NODE_USE_ENV_PROXY=1` for scripts that call Riot.
